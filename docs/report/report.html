1. Overview

A production-style calculator REST service wrapped in a fully automated delivery pipeline. Every commit pushed (or pull request merged) to main is checked out by Jenkins, compiled, unit- and integration-tested, packaged into a hardened multi-stage Docker image, published to Docker Hub under an immutable build-number tag, and deployed as a two-container Compose stack (the API behind an Nginx proxy). A deployment is accepted only once the new build is proven healthy and serving traffic, and every run ends with an email. Nothing after git push is manual: builds #3 to #15 (Appendix B) were all started by commits.

2. Pipeline & Deployment Architecture

Jenkins runs natively on the same Linux host and owns port 8080, so the API container (which still listens on 8080 internally: EXPOSE, health check and proxy upstream are unchanged) is published on host port 8082, and the Nginx proxy on 8081. Both containers share the custom bridge network calc-net; Nginx reaches the API by its service name calculator-app.

3. Jenkins CI/CD Pipeline (declarative Jenkinsfile)

6 DeployDOCKER_IMAGE=…:${BUILD_NUMBER} docker compose up -d --remove-orphans; recreate nginx-proxy only if nginx.conf changed; poll up to 30 × 5 sPasses only when /actuator/health is UP (:8082), /api/v1/add?a=2&b=3 returns 5 through the proxy (:8081), and /actuator/info reports this build number, which proves the new container serves traffic. Otherwise it prints compose ps/logs and fails.
  • Automatic triggering: triggers { githubPush(); pollSCM('H/5 * * * *') }. A GitHub webhook (push events → /github-webhook/ through an ngrok static-domain tunnel to the Jenkins host) starts a build within seconds: build #15 began 8 s after its push (Appendix C.7). Polling every five minutes is the fallback whenever the tunnel is down; it started builds #3–#14.
  • Notifications: post { success {…} failure {…} } calls emailext (falling back to mail) through Gmail SMTP, with job name, build number, image tag, duration and build URL. The failure mail attaches the console log.
  • Re-runnable and idempotent: disableConcurrentBuilds(), a fixed Compose project name, immutable tags and --remove-orphans. Re-deploying the same tag is a no-op, and a new tag replaces only calculator-app while Nginx keeps serving. A cleanup step keeps the three newest tags on the host; timestamps(), a 30-minute timeout and log rotation are enabled.

4. Containerisation and Deployment

Multi-stage Dockerfile

  • Builder (maven:3.9-eclipse-temurin-17-alpine): copies pom.xml first and runs mvn dependency:go-offline, giving a dependency layer that is reused until the POM changes (verified: a source-only change re-runs just COPY src + package). It then copies src/ and runs mvn clean package -DskipTests.
  • Runtime (eclipse-temurin:17-jre-alpine, JRE only, no JDK or Maven): curl for health checks; dedicated non-root appuser:appgroup; only the JAR is copied (root-owned and read-only to the app); EXPOSE 8080; HEALTHCHECK on /actuator/health; exec-form ENTRYPOINT ["java","-jar","/app/app.jar"] so the JVM is PID 1 and shuts down gracefully on SIGTERM; -XX:MaxRAMPercentage=75 respects container memory limits.
  • Per-build values are declared last (cache-friendly): BUILD_NUMBER → /actuator/info, plus OCI version/revision/created labels.
  • .dockerignore limits the context to pom.xml + src/. The image is ≈90 MB compressed and runs with a single docker run -p 8082:8080 aarpeet/calculator-api.

docker-compose.yml + Nginx

  • calculator-app: image ${DOCKER_IMAGE:-aarpeet/calculator-api:latest} with build: . fallback; SPRING_PROFILES_ACTIVE=prod, SERVER_PORT=8080; health check curl /actuator/health (10 s / 5 s / 5 retries / 20 s start period); restart: unless-stopped.
  • nginx-proxy (second component): nginx:stable-alpine, nginx.conf mounted read-only, 8081:80, depends_on: calculator-app: condition: service_healthy, its own health check.
  • Network calc-net (custom bridge). A single docker compose up -d starts the whole stack.
  • Hardening: read-only root filesystems (tmpfs only where needed), no-new-privileges, limits (API 512 MB / 1 CPU, proxy 64 MB / 0.5 CPU), log rotation (3 × 10 MB), 30 s stop grace period.
  • Nginx: per-request DNS via Docker's resolver (survives container IP changes), security headers, rate limiting (20 req/s, burst 40 → HTTP 429), and JSON bodies for proxy errors (429/503).

  • Design: Spring Boot 3.5 / Java 17, layered controller → service. BigDecimal gives exact results (0.1 + 0.2 = 0.3) rendered as clean numbers (5, 2.5).
  • Validation: a @ControllerAdvice maps MissingServletRequestParameterException, MethodArgumentTypeMismatchException and ArithmeticException/IllegalArgumentException to HTTP 400 with {error, status, timestamp}. Operands are bounded to [1e-100, 1e100] so input like 1e999999999 cannot exhaust memory.
  • Tests (mvn test → JUnit XML in target/surefire-reports): CalculatorServiceTest, 33 parameterised unit tests (every operation, negatives, decimals, zero, non-terminating division, divide-by-zero, range); CalculatorControllerIntegrationTest, 16 @SpringBootTest + MockMvc tests (all endpoints, health/info, byte-exact JSON, every 400 case).
  • Coverage (JaCoCo): 95.6% line, 100% branch, 97.8% instruction. Only main() is uncovered.

  • Progressive history: 27 commits on main between 27 Oct 2026 and 30 Oct 2026. Features were developed on 7 branches and merged through pull requests with merge commits (#1–#7); small follow-up fixes were committed directly to main. See the graph in Appendix C.6.

7. Challenges Faced and Solutions

#ChallengeEngineering solution
1Port clash: Jenkins runs natively on host port 8080, so the API cannot publish 8080:8080.The container still listens on 8080; only the host mapping changed to ${APP_HOST_PORT:-8082}:8080, and the proxy runs on 8081.
2Stale proxy after redeploy: Nginx resolves upstream names once at start-up; a recreated API container with a new IP would give 502s.resolver 127.0.0.11 + proxy_pass through a variable forces per-request DNS. Verified by forcing the API IP to change (.2 → .4) with no proxy restart.
3Idempotent deploys from two places: the Jenkins workspace and a developer checkout would create two Compose projects fighting over ports.Fixed Compose project name, disableConcurrentBuilds(), immutable tags; a re-run with the same tag is a verified no-op.
4Clean numeric output: double gives 0.30000000000000004 and 5.0; stripTrailingZeros() gives 1E+1.BigDecimal, normalised scale, Jackson WRITE_BIGDECIMAL_AS_PLAIN; byte-exact JSON asserted in tests.
5Resource-exhaustion input: a=1e999999999 parses as a valid BigDecimal but would expand to a billion digits.Operand magnitude bounded to [1e-100, 1e100] → HTTP 400, covered by unit and integration tests.
6Secrets in CI: Groovy-interpolated credentials leak into process lists and logs.credentials() binding, single-quoted sh, --password-stdin, docker logout in post { always }, access tokens instead of passwords.
7Jenkins execution context: steps run as user jenkins under /bin/sh (dash), initially without Docker access.jenkins added to the docker group; POSIX sh blocks tested under /bin/sh -xe (incl. failure path); Jenkinsfile linted.
8Silent email failure: the log said Sending email to: … but nothing arrived, because email-ext hides SMTP errors outside debug mode.Debug mode exposed Gmail's 535-5.7.8 login rejection; fixed with a Gmail App Password, and the recipient moved to Gmail because the institute's Microsoft 365 mailbox filtered the mails.
9Proxy config never went live: after a green build the new Nginx headers were missing; a single-file bind mount pins the file that existed at container start, and git checkout replaces it.The Deploy stage compares the config inside the container with the checked-out file and recreates only nginx-proxy when they differ; re-runs stay no-ops.
10Exposed CI server: anonymous users held the Jenkins admin role, which through a public webhook tunnel would allow remote code execution.Role-based authorisation locked down: admin only for the owner's account, no anonymous permissions; only /github-webhook/ stays open.

8. Conclusion

All six required stages run automatically on every change, with published test results, credentials kept out of the code, verified deployments and email notifications. The pipeline ran end to end 15 times, including a deliberately failing commit that was stopped at the Test stage without affecting the running service. The Capstone will extend this pipeline with Ansible, Kubernetes and Prometheus/Grafana.
